# ScanServer

Локальный Python-клиент (Python 3.12) для работы с промышленными
QR/штрих-сканерами по COM-порту. Поддерживает несколько физических
сканеров одновременно, изолированные сессии, режимы обработки
(COMPARE_FILL, COMPARE, DEFECT, TRANSFER, TRANSFER_DEFECT, PACKAGE, STRETCH), озвучку через
edge-tts с кэшированием и fallback, работу с Laravel API.

------------------------------------------------------------------------

# Устройство проекта

- `main.py` — запуск, загрузка конфигурации, проверка обновлений и остановка приложения.
- `scanner/manager.py` — создаёт отдельную сессию для каждого сканера из `config.json`.
- `scanner/com_reader.py` — чтение QR из COM-порта и переподключение.
- `scanner/session.py` — пользователь, режим, таймаут активности и общий формат событий MES.
- `scanner/router.py`, `scanner/svc_commands.py` — сервисные QR и передача рабочих QR в режим.
- `modes/` — обработчики режимов; `ui/` — окна ввода брака и переноса.
- `api/` — HTTP-клиент MES и кэш пользователей.
- `tts/` — очередь озвучки, кэш аудио и резервный движок речи.
- `core/` — конфигурация, состояние, логирование и обновления из GitHub Releases.

Путь рабочего QR: COM-порт → сессия сканера → роутер → текущий режим → MES.
Режим сохраняется в `state.json` для каждого устройства; при запуске пользователь выбирается заново.

# Возможности

## Многосканерная архитектура

-   Каждый физический сканер = отдельная сессия
-   Свой device_id
-   Свой текущий пользователь
-   Свой режим работы
-   Изоляция потоков

## Управление пользователями

-   Установка пользователя через QR: `SVC:USER:{id}`
-   Повторный скан того же ID → снимает пользователя
-   Скан другого ID → переключает пользователя
-   Автоматический сброс через 15 минут без активности
-   При запуске программы пользователь всегда отсутствует

## Режимы работы

Переключение режимов сервисными QR:

SVC:MODE:COMPARE_FILL\
SVC:MODE:COMPARE\
SVC:MODE:DEFECT\
SVC:MODE:TRANSFER\
SVC:MODE:TRANSFER_DEFECT\
SVC:MODE:PACKAGE\
SVC:MODE:STRETCH

# COMPARE_FILL

Нужно отсканировать три QR с совпадающим артикулом в любом порядке.
Хотя бы один QR должен содержать полные данные (поле `art` и другие поля).
После третьего совпадения этот полный QR отправляется на резку с `action=done`.
При несовпадении — «Не верно», при отсутствии полного QR — «Не найден QR с данными».

Поддерживаемые форматы:

WALLPAPER\|v=1\|oi=1\|art=DL-001\|w=300\|h=270\|panels=3\|kind=striped\|lk=...\|code=...

Берётся art=DL-001

FFO-065_500х270\|0

Берётся FFO-065_500х270

------------------------------------------------------------------------

# DEFECT

После сканирования рабочего QR открывается окно: - Пользователь - Тип
изделия (Футболки / Обои) - Поле ввода - Комментарий - Отправить /
Отмена

### Футболки

Вводится общее количество:
Футболки → qty\

### Обои
Вводятся номера полотен:
Полотна = 1,2,3

→ преобразуется в:
```json
"panels": [1,2,3]
```
action = "defect"

------------------------------------------------------------------------

# TRANSFER

Скан QR → окно размеров: XS, S, M, L, XL, 2XL, 3XL, 4XL, 5XL

Формируется done_map:
```json
{ "XS": 5, "M": 2 }
```
action = "done"

------------------------------------------------------------------------

# TRANSFER_DEFECT

Аналог TRANSFER, но: - есть комментарий - action = "defect"

------------------------------------------------------------------------

# STRETCH — Натяжка

1. Выбрать пользователя сервисным QR `SVC:USER:{id}`.
2. Выбрать режим сервисным QR `SVC:MODE:STRETCH`.
3. Один раз отсканировать рабочий QR.

Исходная строка QR отправляется с `action=done` последовательно:

1. `POST /api/v1/cut/scan` — резка (`endpoints.events`).
2. После успешного ответа резки: `POST /api/v1/stretch/scan` — натяжка (`endpoints.stretch`).

Оба запроса используют общий формат событий: `payload`, `action`, `user_id`,
`device_id`, `client_ts`. Выбор и проверка пользователя такие же, как в других режимах.
После успешного ответа на оба запроса звучит «Натяжка выполнена».

При ошибке резки запрос натяжки не отправляется. При ошибке натяжки озвучивается:
«Резка отправлена. Ошибка отправки натяжки». При сетевой ошибке добавляется
«Нет соединения с сервером». Автоматических повторов и отката резки нет;
повторное сканирование снова запускает оба этапа.

Путь натяжки можно изменить через `endpoints.stretch` в `config.json`.
Старый конфиг без этого поля использует `/api/v1/stretch/scan` по умолчанию.


# Работа с сервером

## Получение пользователя

    GET /api/v1/users/{id}

### Ответ:

``` json
{
  "id": 8,
  "name": "Admin Root"
}
```

### Ошибки:

-   404 → "Неверный id пользователя"
-   Network error → "Нет соединения с сервером"

------------------------------------------------------------------------

## Формат отправки на сервер

### Общий формат:

``` json
{
  "payload": "RAW_QR_STRING",
  "action": "done | defect",
  "user_id": 8,
  "device_id": "BG01",
  "client_ts": "2026-02-10T17:10:57+03:00"
}
```

### Дополнительно в зависимости от режима:

#### DONE (TRANSFER)

``` json
"done_map": {
  "XS": 5,
  "L": 2
}
```

#### DEFECT (WALLPAPER)

``` json
"panels": [1,2,3]
```

#### DEFECT (TSHIRT)

``` json
"qty": 3
```

#### Комментарий

``` json
"reason": "кривой перенос"
```
